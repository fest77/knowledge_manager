## 三、总纲固化的 17 条跨模块强制规则（ER）

总纲 `00_模块划分与边界.md` §2 是本批 Spec 的"宪法"。它把 **2.3 项目实际踩过的三类缺陷** 变成了可自动校验的规则：

| 类型 | 规则 | 2.3 的教训 |
|---|---|---|
| **错误码撞码** | **ER-01** 一模块一前缀，禁止共用 | 2.3 曾出现 `05/06` 共用 `RUL`、`07/08` 共用 `CAS`、`02/11` 共用 `MET` 但含义完全不同 |
| **实体多写者** | **ER-02** 一个实体只有一个归属模块（单一写入者） | 2.3 的 `device_user_cnt` 被两个模块各写一份，口径分叉 |
| **鉴权逻辑分叉** | **ER-03** 数据权限判定只有一份实现（在 05 模块） | 本项目最严重的缺陷类型：**越权泄漏** |
| **fail-open** | **ER-04** 鉴权 fail-closed（查不到就拒绝） | 数据库抖动时放行 = 把私密文档泄漏给全员 |
| **审计旁路** | **ER-05** 审计只能经 `AuditService` | 字段缺失、动作名不统一 |
| **一份数据两用双写** | **ER-06 / ER-07** `qa_logs` 只由 06 写、指标桶只由 09 写 | 双写必冲突 |
| **权限回写向量库** | **ER-11 / ER-12** 权限不进 Milvus、切片不冗余权限字段 | 违反 AD-02/AD-03：权限变更不再即时生效 |
| **N+1 查询** | **ER-13** 批量取权限必须一次 `IN` 查完 | 50 个切片 = 50 次查询 |
| **SSE 越权窃听** | **ER-14** 订阅必须校验归属 | 存量 `sse_util` 的真实安全缺陷：拿到 `task_id` 就能窃听 |
| **编号命名空间抢占** | **ER-16** 模块内决策用 `DEC-{模块号}-x`，不得占用 `D-xx` | 子 agent 曾把模块内决策编成 `D-07-x`，与 Step 2 的 `D-01~D-06` 撞名 |
| **擅改上游字段表** | **ER-17** 加字段必须在 §8 登记后由 Step 1 统一回填 | 各模块各自加字段 → 实体设计失效 |

（完整 17 条见总纲 §2，逐条含"违反后果"。）
