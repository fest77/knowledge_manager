## 三、接口契约

### 3.1 `GET /api/v1/system/config` — 读取配置

| 项 | 内容 |
|---|---|
| 功能权限 | `model:config` |
| 出参 | `{ "items": [ { key, group, label, value, value_type, default_value, editable, description, minimum, maximum } ] }` |
| 顺序 | 按 `ConfigGroup` 声明顺序分组（llm → retrieval → faq → gap → import） |

> `minimum` / `maximum` **不在 E22 的字段表里**，它们来自代码侧的 `PRESET`
> （校验策略属于代码，不属于数据）。接口把它们透出去是为了让前端能做输入约束，
> 避免"前端让填、后端才拒"的往返。

### 3.2 `PUT /api/v1/system/config` — 保存配置（热生效）

| 项 | 内容 |
|---|---|
| 功能权限 | `system:config` |
| 入参 | `{ "values": { "<配置键>": <新值> }, "reason": "≥5 字" }` |
| 出参 | `{ "changed": [...], "unchanged": [...], "items": [...最新全量...] }` |

**服务端规则**

| # | 规则 | 失败 |
|---|---|---|
| 1 | `reason` 必填且 ≥5 字（配置变更要写审计，与四维权限变更 G-11 同口径） | `SYS-1001` |
| 2 | `values` 不能为空 | `SYS-1001` |
| 3 | 未知配置键 | `SYS-1001` |
| 4 | 不可编辑项（`llm.model` / `embedding.model` / `rerank.model`，须改 `.env`） | `SYS-1001` |
| 5 | 类型不符（如给 int 传 `"abc"`、布尔冒充数字） | `SYS-1001` |
| 6 | 超出 `minimum` / `maximum` | `SYS-1001` |
| 7 | **先全量校验后写入**：任一项不合法则**整批不生效** | — |
| 8 | 值未变化 → 进 `unchanged`，**不写库、不 +version** | — |
| 9 | 成功后立即刷新内存，**无需重启** | — |

**错误码**

| 码 | HTTP | 触发 |
|---|---|---|
| `AUTH-2003` | 401 | 无令牌 / 令牌无效 |
| `AUTH-2004` | 403 | 缺 `model:config`（读）或 `system:config`（写） |
| `SYS-1001` | 400 | 上表 1~6 任一 |

## 四、数据模型：E22 `system_config`

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 配置键（点分命名，如 `llm.temperature`） |
| `group` | enum | `llm` / `retrieval` / `faq` / `gap` / `import` |
| `label` | string | 中文名（界面渲染） |
| `value` | any | 当前值 |
| `value_type` | enum | `string` / `int` / `float` / `bool` / `json` |
| `default_value` | any | 默认值（"恢复默认"用） |
| `editable` | bool | 是否允许界面修改 |
| `description` | string | 说明 |
| `version` | int | 每次成功修改 +1 |
| `updated_by` / `updated_at` | — | 操作人与时间 |

**9 个预置项**

| 配置键 | 分组 | 中文名 | 默认值 | 范围 | 关联悬空点 |
|---|---|---|---|---|---|
| `llm.model` | llm | 对话大模型 | `qwen-flash` | — | 不可编辑 |
| `llm.temperature` | llm | 温度 temperature | `0.2` | 0 ~ 2 | — |
| `llm.max_tokens` | llm | 最大输出长度 | `2048` | 64 ~ 8192 | — |
| `embedding.model` | retrieval | Embedding 模型 | `BGE-M3（本地 · CUDA）` | — | 不可编辑 |
| `rerank.model` | retrieval | Rerank 模型 | `bge-reranker-large` | — | 不可编辑 |
| `retrieval.recall_multiplier` | retrieval | 召回放大倍数 | `5` | 1 ~ 20 | **G-04** |
| `faq.cache_sim_threshold` | faq | FAQ 缓存命中阈值 | `0.92` | 0.5 ~ 1 | **G-03** |
| `gap.score_threshold` | gap | 缺口判定阈值 | `0.75` | 0 ~ 1 | **G-06** |
| `import.concurrency` | import | 导入并发上限 | `2` | 1 ~ 8 | AD-09 |

**三条设计约定**

1. **定义在代码、值在库**：键/分组/类型/默认值/范围集中在 `config_service.PRESET`；
   库里存值。避免"库里说它是 int、代码当字符串用"的漂移。
2. **受控集合**：只有 `PRESET` 里的键对外可见/可改；有人手插一行不会凭空多出开关。
3. **bootstrap 不覆盖**：启动时只插入缺失项，**已存在的一律不覆盖**——管理员改过的阈值
   不会被重启或重跑种子冲掉。

## 五、功能权限机制（ER-08 / ER-09 的落地）

**认证与授权分成两处，这是刻意的**：

| 关注点 | 位置 | 为什么不能放一起 |
|---|---|---|
| **认证**（你是谁） | JWT 中间件 | 必须早于路由匹配，才能拦住不存在的路径；还要负责白名单 |
| **授权**（你能不能） | `enforce_perm` **依赖** | 需要 `request.scope["route"]`，它只在路由匹配之后才存在 |

`enforce_perm` 通过 `FastAPI(dependencies=[Depends(enforce_perm)])` **全局注册**——
挂在 app 上就不必逐个路由声明，「忘了加权限」这类漏网之鱼从结构上被消除。

路由侧声明：`@require_perm("audit:read")`，**OR 语义**（命中任一即可）。

## 六、前端壳的设计

| 决定 | 理由 |
|---|---|
| **hash 路由**（`#/docs`）而非 History API | 静态托管没有 SPA fallback，`/ui/docs` 会 404；hash 永远只请求 `/ui/` |
| **ES module** 而非全局脚本 | 原生支持、无需打包器，且 import/export 让依赖关系显式 |
| 菜单**不做前端权限推导** | `GET /auth/me` 的 `menus` 已是后端算好的（模块 01 §3.2）；前端只渲染 |
| **未实现的菜单灰显 + 「待开发」角标 + 摘掉 href** | 后端会给出 `#/qa`、`#/dashboard`、`#/audit` 等尚未开发的菜单。把它们渲染成可点是"看起来能用其实不能用"，比不可点更糟 |
| 点进未实现路由 → 显示**归属哪个模块** | 给人一个明确交代，而不是白屏 |

路由表集中在 `web/js/app.js` 注册，因此"哪些页面已实现"只有**一个事实源**，
侧边栏据此判断灰显——不会出现两处清单不一致。
