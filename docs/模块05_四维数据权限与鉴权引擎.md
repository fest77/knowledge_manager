## 三、接口契约

| 方法 | 路径 | 功能权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/perm/{doc_id}` | `perm:manage` | 配置回显；**无记录返回默认值 + `version=0`，不返回 404** |
| PUT | `/api/v1/perm/{doc_id}` | `perm:manage` | 保存四维 + 原因（≥5 字）；返回 `version` 与 `effective_immediately=true` |
| POST | `/api/v1/perm/check` | `perm:check` | 判定接口；**HTTP 恒为 200** |

### 3.1 判定响应为什么不含文档内容（AC-05-10）

```jsonc
{ "doc_id": "...", "allowed": false, "reason_code": "none_matched",
  "evaluated_as": { "user_id": "...", "dept_id": "...", "role_ids": [...] },
  "version": 7 }
```

只有 `doc_id` + 判定结果 + 判定依据。**一旦出现标题或正文，这个接口就变成了
越权读取通道**（能猜出 `doc_id` 就能拿到内容）——所以有专门的用例断言
响应文本里不含标题、文件名、`content` 等字样。

### 3.2 路由顺序

`/perm/check` 必须声明在 `/perm/{doc_id}` **之前**。
写反的话 `PUT /perm/check` 会命中 `{doc_id}="check"` 并报 `PERM-3001`
（看起来像"文档不存在"，实际是路由被吃掉了）。

## 四、数据模型

### 4.1 E07 `kb_permissions`

一条记录 = 一篇文档的阅读权限。5 个索引：

| 索引 | 用途 |
|---|---|
| **`doc_id` 唯一** | 鉴权主查询（全系统最高频）；也是"一个文档最多一条权限记录"的强制手段 |
| `is_global` | 看板统计公开知识数 |
| `departments` / `roles` / `users` | 多键索引，反查"该部门被授权了哪些文档"（`ORG-3008`、管理端排查） |

`version` 每次变更 +1，是缓存 key 与审计追溯的依据（R-7）。

### 4.2 `permission_summary`（E04 的展示摘要，**不参与鉴权**）

```jsonc
{ "is_global": false, "dept_cnt": 2, "role_cnt": 1, "user_cnt": 0,
  "version": 7, "label": "limited" }
```

`version` 由 05 带上、由 03 落库：03 据此判断摘要是否过期。
**AC-05-15 专测"摘要是公开也不能读"** —— 鉴权只读 E07。

## 五、判定语义（Spec §1.4 / §4.3）

```
allow(user, doc) = is_global
                OR user.dept_id ∈ departments      ← 精确匹配，不含子部门（G-02）
                OR user.role_ids ∩ roles ≠ ∅
                OR user.user_id ∈ users
```

| 情形 | 结果 | reason_code |
|---|---|---|
| 无权限记录 | **拒绝** | `no_permission_record` |
| 记录存在但四维都没匹配 | 拒绝 | `none_matched` |
| 查库异常 | **全部拒绝** + `degraded=true` | `engine_degraded` |
| 命中全局 / 部门 / 角色 / 个人 | 放行 | `global` / `department` / `role` / `user` |

**判定内核是纯函数**（`evaluate_record(user, record)`）：无 IO，
所以批量判定 50 条 < 1ms 的预算有保障，而且能被穷举测试。
ER-03 要求"权限判定只有一份实现"，把内核做成纯函数是最直接的落实方式。

### 5.1 三条最容易被"好心"破坏的铁律

| 铁律 | 为什么不能让步 |
|---|---|
| **`sys_admin` 也不能读未授权的文档**（AC-05-03） | 让管理员默认绕过 = 留一个"拿到管理员账号就能看全部知识"的后门。管理员要读就**显式配权限**，留下记录而不是靠身份 |
| **部门授权不含子部门**（G-02 / AC-05-04） | 授权"财务部"时若连带"报销组"，配置者以为自己只开了 3 个人，实际开了 30 个 |
| **查库异常必须全拒**（ER-04 / AC-05-08） | fail-open 的失败模式是"数据库抖动 → 私密文档泄漏给全员"；fail-closed 的代价只是"这次没答上来"，可以重试 |

### 5.2 为什么能"即时生效"（AD-02 / AD-03）

| 环节 | 本项目做法 |
|---|---|
| 权限存哪 | **只存文档级 E07 一条** |
| 改权限时 | 只写一条记录（< 10ms），**不碰 Milvus** |
| 何时生效 | **下一次请求立即生效**（缓存也按 `version` 自然失效） |
| 检索时 | Milvus 只按 `enabled == true` 召回，应用层按 `doc_id` 判定 |
| 代价 | 召回 Top-K 可能被过滤 → 由 06 用 `retrieval.recall_multiplier`（默认 5）补偿 |

有一条用例用"任何 Milvus 调用都抛异常"来验证改权限确实不碰向量库。

## 六、错误码（13 个 `PERM-*`）

| 码 | HTTP | 触发 |
|---|---|---|
| `PERM-1001` | 400 | 变更原因缺失或 < 5 字（G-11） |
| `PERM-1002` / `1003` / `1004` | 400 | 部门（不存在或已停用）/ 角色 / 用户无效 |
| `PERM-1005` | 400 | 单维超过 200 项 |
| `PERM-1006` | 400 | 维度不是数组 |
| `PERM-2001` | 403 | 非系统管理员代查他人判定结果 |
| `PERM-2002` | 403 | 无 `perm:manage`（服务层兜底；正常路径由 00 的全局依赖产出 `AUTH-2004`） |
| `PERM-3001` | 404 | 文档不存在或已软删除 |
| `PERM-3002` | 404 | 权限记录不存在（仅内部"必须已配置"的场景） |
| `PERM-4001` | 500 | E07 写入失败 |
| `PERM-4002` | 500 | 摘要刷新失败（**权限已保存**；只记 WARN，不给用户报错） |
| `PERM-5001` | 500 | 判定过程未预期异常（调用方必须按 deny 处理） |

**`PERM-4002` 的语义值得单独说**：权限记录已经写成功了，只是 E04 的展示标签没刷新。
因为"摘要不是鉴权依据"（鉴权只读 E07），所以这**不影响正确性**，
只记 WARN 并重试一次，**不把错误返回给用户**。有一条用例专门验证这一点。
